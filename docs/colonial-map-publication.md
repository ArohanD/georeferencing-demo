The local publication receipts report successful raster and metadata uploads. REST administration still requires authentication; no security settings were changed.

| `history:wimble_1738` | [James Wimble, 1738](https://digital.lib.ecu.edu/1068), coastal NC chart | 9.6 MB, EPSG:3857, 125 m pixels | 21.3 km RMSE; 3 cape proxies |
| `history:bowen_1747` | [Emanuel Bowen, 1747](https://dlg.usg.edu/record/guan_hmap_hmap1747b6), **coastal NC excerpt** of the Carolinas/Georgia map | 14.1 MB, EPSG:3857, 200 m pixels | 13.9 km RMSE; 3 cape proxies |

Approximate historical-map alignment. For visual comparison only; not suitable for locating routes or sites precisely.

Five named town symbols per map were paired with frozen USGS GNIS modern populated-place centers and fit with an unweighted affine transformation in EPSG:32119. Three separately selected cape points were withheld. Town-center correspondence, shoreline migration, historical survey distortions and the GNIS cape-point definitions are uncertain. These RMSE values are discrepancy diagnostics, **not survey-grade accuracy estimates**. Interior areas are unvalidated. Output pixel sizes do not imply positional accuracy. Source-pixel coordinates start at the upper-left of the exact downloaded JPEG (x right, y down). All selections and fit/check roles were frozen before fitting; no checkpoint tuning was performed.

Wimble's decorative panels are masked; Bowen is deliberately limited to the coastal region near the controls. The complete unrectified source scans are retained. The maps do not establish specific river crossing locations.

## Files and metadata

Each `data/historical_maps/{wimble_1738,bowen_1747}/` contains `source.json`, `points.json`, `transformation.json`, `manifest.json`, institutional IIIF metadata, and `visual-review.json`. The manifests include source/derivative checksums, creators, date, attribution, catalog and download URLs, rights, method, point selections, residuals, bounds, CRS, masks and raster validation. `colonial-cape-references.json` preserves the public USGS reference response and request URL.

Each corresponding ignored `deliverables/` directory contains:

- `source.jpg`: institutional scan derivative.
- `<id>_approximate_master_32119.tif`: state-plane RGBA COG.
- `<id>_approximate_web_3857.tif`: serving RGBA COG with overviews and embedded provenance/points/transformation tags.
- Metadata copies, `point-evidence.jpg`, `rectified-overview.png`, and USGS comparison images.
- `coverage.xml` and `layer.xml`: reviewable GeoServer metadata payloads, generated by the publisher's dry-run.

ECU marks its Wimble reproduction **InC-EDU / educational use permitted**, with research, teaching and private-study language. It is a reproduction from a 1969 article, not an unrestricted scan merely because the original chart is from 1738. Preserve ECU's credit and rights statement for this GIS590 educational prototype. Bowen's institutional record says **No Copyright—United States**. Both statements are preserved in source metadata and GeoServer payloads.

The later 1808/1833 drafts were set aside after the colonial-era preference arrived. They are excluded from the publishing allowlist, remain only under ignored `deliverables/`, and must not be published.

## Run the upload from this checkout

The existing `.venv313` has the required Python dependencies. First inspect the plan (no network or server changes):

```bash
cd /home/arohan/code/georef
.venv313/bin/python tools/processing/publish_historical_maps.py
```

Then publish both layers:

```bash
.venv313/bin/python tools/processing/publish_historical_maps.py --publish
```

The script prompts for your GeoServer username and password in the terminal. The password is hidden and never written to disk or passed on the command line. `GEOSERVER_USERNAME` optionally supplies the username; there is no password file or browser credential. Do not paste credentials into chat.

It checks the existing `history` workspace, refuses existing stores/layers, uploads each GeoTIFF through `PUT .../coveragestores/<id>/file.geotiff?configure=first&coverageName=<id>`, sets coverage title/abstract/keywords/source and rights links, stores the complete manifest under `historicalMapMetadata`, and sets layer attribution and the raster style. It verifies a metadata round trip and then requests **two anonymous WMS PNG images** per layer. Credentials are not used for WMS verification. HTTPS validation stays enabled; redirects are rejected. REST reference: [GeoServer coverage stores](https://docs.geoserver.org/stable/en/user/rest/api/coveragestores/).

Success produces `publication-receipt.json` and `published-*.png` in each layer's deliverables folder. These are the publication evidence; the build manifests remain preparation records. Inspect the returned images before enabling layers in `app/public/preview/map-config.js`.

If a upload succeeded but metadata/WMS checking failed, rerun with `--publish --resume`. Resume requires a matching local receipt and never reuploads raster bytes into an existing store. Use `--layer wimble_1738` or `--layer bowen_1747` to work on one. If the upload failed before a receipt was saved but created a server store, inspect that new store in GeoServer; the script intentionally refuses to overwrite it automatically.

Anonymous verification can be repeated without credentials:

```bash
.venv313/bin/python tools/processing/publish_historical_maps.py --verify-only
```

## If IIS blocks the upload

401 means valid GeoServer publishing credentials are needed; 403 means the account lacks permission. Do not change anonymous REST security to make this work.

For a 413 upload-size rejection, copy the two **web** TIFFs to `C:\GIS590_adutt2\Data\HistoricalMaps` on the VCL server. Compare PowerShell `Get-FileHash -Algorithm SHA256` for those files with the dry-run's hashes, then register the copied files and send their metadata:

```bash
.venv313/bin/python tools/processing/publish_historical_maps.py --publish \
  --server-dir 'C:\GIS590_adutt2\Data\HistoricalMaps'
```

This uses `external.geotiff` and sends only server-local file URIs. The directory must exist **on the GeoServer machine** and the GeoServer service account needs read access. It does not make the browser depend on a Windows/network drive. Keep the files there after registration. No IIS/firewall changes are needed for this fallback.
